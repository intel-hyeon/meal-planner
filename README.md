## 1. 제작한 것 소개

매주 식단을 계획하고 마트에 가기 전 장보기 목록을 정리하는 20대 대학생 및 1인 가구를 위한 실생활 밀착형 웹 앱입니다.

### 현재 구현된 주요 기능 (1~3단계 완료 시점)
- **레시피 동적 CRUD:** 재료명(20자 제한), 수량(양의 실수 제약), 단위(10자 제한) 입력 폼 제공
- **동적 행 추가/삭제:** `+` 버튼으로 재료 칸 동적 추가 (최대 100개 상한 제한), `-` 버튼으로 해당 행 즉시 삭제
- **기준 인분 수(N) 설정:** 레시피별로 기준 인분 수를 지정할 수 있는 입력 폼 제공
- **빈칸 자동 정제 (Cleanup):** 재료 입력란 중 내용이 없는 공란 행은 저장 시 자동으로 걸러져 화면과 로컬 캐시에서 완전 증발
- **장바구니 담기 토글:** 레시피 카드에서 버튼 한 번으로 장바구니에 손쉽게 추가/제거
- **인분 수 비례 연산 (M인분):** 목표 인분 수 조절 시 `기존 양 × (M / N)` 공식을 자동 적용하고, 소수점 셋째 자리 버림(Floor)으로 정밀 보정
- **중복 식재료 합산 & 정렬:** 이름과 단위가 완전히 동일한 재료만 안전하게 합산하고, 가나다/알파벳 순으로 정렬하여 2단 분할 레이아웃으로 출력
- **로컬 캐시 영속화:** `localStorage`를 통해 브라우저를 껐다 켜거나 새로고침(F5)해도 모든 레시피 및 장바구니 상태 안전 보존
- **GitHub Pages 클라우드 배포:** GitHub Actions를 연동하여 소스 푸시 시 자동으로 정적 호스팅 배포

## 3. Todo 리스트의 변경 내역 (피드백 반영)

바이브 코딩을 진행하며 사용자가 브라우저에서 직접 테스트하고 제시한 피드백과 편의성 개선 의사결정을 반영하여 초기 계획을 아래와 같이 수정했습니다:

| 구분 | 초기 계획 (v0) | 사용자 피드백 및 변경 내용 (v1) | 변경 사유 및 근거 |
|---|---|---|---|
| **프로젝트 타이틀** | `주간 식단 플래너 & 장바구니` | `식단 플래너 & 장바구니` | 특정 주기에 국한되지 않고 다목적으로 활용할 수 있도록 간소화 요청 |
| **플레이스홀더 예시** | `예: 백종원 김치찌개, 된장찌개` | `예: 김치찌개, 된장찌개` | 특정 인명 수식어를 배제하고 담백한 메뉴명 위주로 노출 요청 |
| **모달 상단 중복 문구** | `저장 시 내용이 없는 빈칸 행은 자동으로 정리(증발)됩니다.` 노출 | 모달 헤더 문장 제거 | 하단의 *"💡 입력하지 않고 남겨둔 빈 재료 칸은..."* 안내와 한 화면에서 중복 서술되므로 시각적 피로도 감소를 위해 제거 |
| **레시피 목록 안내 문구** | `레시피를 등록하면 빈칸은 자동으로 정리되며...` 노출 | 문장 완전 제거 | 카드 목록에 온전히 집중할 수 있도록 안내성 텍스트 제거 |
| **장바구니 탭 명칭** | `장바구니 및 비례 계산 목록`, `(M)인분` 노출 | `장바구니`, `(M)` 표기 제거 | 수식 변수 노출을 지양하고 직관적인 '요리할 인분 수'로 일상적 표현 적용 |
| **배포 방식 전환 (주요 변경)** | `npm run dev` 로컬 실행 방식 | **GitHub Pages 클라우드 자동 배포** (`.github/workflows/deploy.yml` + `vite.config.ts base: './'`) | **과제 평가자 및 사용자가 복잡한 터미널 명령어 설치 과정 없이 웹 브라우저 링크 하나로 즉시 앱을 실행하고 검증할 수 있도록 클라우드 환경으로 이전 결정** |

## 4. 사용한 스킬

본 프로젝트에서는 복잡한 식재료 비례 연산과 단위 일치 규칙, 로컬 스토리지 무결성을 검증하기 위해 **`meal-planner-qa`** 스킬 절차를 준수하며 개발하고 있습니다.

- **스킬 목적:** 소수점 셋째 자리 버림 규칙 준수, 동일 재료명-단위 완전 일치 그룹화, 로컬스토리지 고아 데이터 방지
- **작업 방식:** AI 에이전트가 각 단계 코드를 구현한 후 빌드 검증 및 엣지 케이스를 자가 점검하고 사용자에게 보고하는 표준 절차로 활용합니다.

## 5. 느낀점 및 결론

- **계획과 화면의 분리:** 화면 인터랙션을 먼저 만들고 세부 데이터 로직을 연결하는 방식을 취하니, 입력 제약이나 행 동적 추가 같은 사용자 경험을 조기에 검증할 수 있었습니다.
- **피드백 루프의 중요성:** AI가 초기에 임의로 작성한 긴 문구나 중복된 설명들을 사용자가 직접 화면을 보며 피드백("중복 문구 제거", "타이틀 간소화")을 주어 훨씬 정제되고 완성도 높은 UI를 구축할 수 있었습니다.
- **배포 방식 전환의 유연성:** 로컬 개발 환경에 머무르지 않고 GitHub Pages 배포로 전환함으로써, `base: './'` 상대경로 처리와 GitHub Actions 워크플로우를 직접 연동해 보는 가치 있는 경험을 얻었습니다.
