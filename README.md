## 1. 제작한 것 소개

매주 식단을 계획하고 마트에 가기 전 장보기 목록을 정리하는 20대 대학생 및 1인 가구를 위한 실생활 밀착형 웹 앱입니다.

### 핵심 기능 및 차별점
- **레시피 동적 CRUD:** 재료명(최대 20자), 수량(양의 실수), 단위(최대 10자) 입력 폼 제공
- **스마트 동적 행 관리:** `+` 버튼으로 재료 칸 동적 추가 (최대 100개 상한 제한), `-` 버튼으로 해당 행 즉시 삭제
- **기준 인분 수(N) 설정:** 레시피별로 기준 인분 수를 지정할 수 있는 입력 폼 제공
- **빈칸 자동 정제 (Cleanup):** 재료 입력란 중 내용이 없는 공란 행은 저장 시 자동으로 걸러져 화면과 로컬 캐시에서 완전 증발
- **장바구니 담기 토글:** 레시피 카드에서 버튼 한 번으로 장바구니에 손쉽게 추가/제거
- **인분 수 비례 연산 (M인분):** 목표 인분 수 조절 시 `기존 양 × (M / N)` 공식을 자동 적용하고, 소수점 셋째 자리 버림(Floor)으로 정밀 보정
- **중복 식재료 합산 & 정렬:** 이름과 단위가 완전히 동일한 재료만 안전하게 합산하고, 가나다/알파벳 순으로 정렬하여 2단 분할 레이아웃으로 출력
- **장바구니 무결성 방어 (Orphan Clean):** 원본 레시피가 삭제되거나 캐시가 변경되어도 장바구니에 쓰레기(null/고아) 데이터가 남지 않도록 듀얼 방어 로직 적용
- **클립보드 원클릭 내보내기:** 최종 정렬·합산된 장보기 목록을 깔끔한 텍스트로 가공하고, 원클릭으로 클립보드에 복사(오프라인/HTTP 폴백 지원) 및 텍스트 미리보기 제공
- **로컬 캐시 영속화:** `localStorage`를 통해 브라우저를 껐다 켜거나 새로고침(F5)해도 모든 레시피 및 장바구니 상태 안전 보존
- **GitHub Pages 클라우드 배포:** GitHub Actions를 연동하여 소스 푸시 시 자동으로 정적 호스팅 배포

## 3. Todo 리스트의 변경 내역 (피드백 반영)

바이브 코딩을 진행하며 사용자가 브라우저에서 직접 테스트하고 제시한 피드백과 편의성 개선 의사결정을 반영하여 초기 계획을 아래와 같이 체계적으로 수정했습니다:

| 발생 시점 | 구분 | 초기 계획 (v0) | 사용자 피드백 및 변경 내용 (v1) | 변경 사유 및 근거 |
|---|---|---|---|---|
| **2단계 완료 후** | **프로젝트 타이틀** | `주간 식단 플래너 & 장바구니` | `식단 플래너 & 장바구니` | 특정 주기에 국한되지 않고 다목적으로 활용할 수 있도록 간소화 요청 |
| **2단계 완료 후** | **플레이스홀더 예시** | `예: 백종원 김치찌개, 된장찌개` | `예: 김치찌개, 된장찌개` | 특정 유명 인명 표기를 배제하고 직관적인 메뉴명 위주로 노출 요청 |
| **2단계 완료 후** | **모달 상단 중복 문구** | `저장 시 내용이 없는 빈칸 행은 자동으로 정리(증발)됩니다.` 노출 | 모달 헤더 문장 제거 | 하단의 *"💡 입력하지 않고 남겨둔 빈 재료 칸은..."* 안내와 한 화면에서 중복 서술되므로 시각적 피로도 감소를 위해 제거 |
| **2단계 완료 후** | **레시피 목록 안내 문구** | `레시피를 등록하면 빈칸은 자동으로 정리되며...` 노출 | 문장 완전 제거 | 카드 목록에 온전히 집중할 수 있도록 불필요한 설명 텍스트 제거 |
| **2단계 완료 후** | **장바구니 탭 명칭** | `장바구니 및 비례 계산 목록`, `(M)인분` 노출 | `장바구니`, `(M)` 표기 제거 | 수식 변수 노출을 지양하고 직관적인 '요리할 인분 수'로 일상적 표현 적용 |
| **3단계 진행 중** | **배포 방식 전환 (주요 변경)** | `npm run dev` 로컬 실행 방식 | **GitHub Pages 클라우드 자동 배포** (`.github/workflows/deploy.yml` + `vite.config.ts base: './'`) | **과제 평가자 및 일반 사용자가 복잡한 터미널 명령어 설치 과정 없이 웹 브라우저 링크 하나로 즉시 앱을 실행하고 검증할 수 있도록 클라우드 환경으로 이전 결정** |
| **5단계 QA 중** | **수량 스피너 버그 개선** | `min="0.001"`로 인해 스피너가 0.001 단위로 증감 | `min="0"` 및 `step="any"` 적용 | 브라우저 기본 화살표 클릭 시 1 단위씩 직관적으로 증감하면서 소수점 입력도 자유롭게 지원하도록 개선 |
| **5단계 QA 중** | **안전하지 않은 버튼 제거** | 상단에 "샘플 복원" 버튼 항상 노출 | "샘플 복원" 버튼 완전 제거 및 캐시 비우기 경고 다이얼로그 강화 | 사용자가 공들여 작성한 레시피 데이터가 실수로 덮어씌워져 유실되는 치명적 사고를 원천 방지 |
| **5단계 완료 후** | **실제 배포 링크 확정** | 임시 placeholder URL 표기 | 실제 GitHub Pages 주소 (`https://intel-hyeon.github.io/meal-planner/`) 확정 연동 | 배포 성공 후 누구나 즉시 접근 가능하도록 라이브 URL 제공 |

## 4. 사용한 스킬

본 프로젝트에서는 복잡한 식재료 비례 연산과 단위 일치 규칙, 로컬 스토리지 무결성을 검증하기 위해 전용 커스텀 Agent Skill인 **`meal-planner-qa`**를 제작하여 개발에 활용했습니다.

- 📁 **스킬 정의 파일:** [skills/meal-planner-qa/SKILL.md](./skills/meal-planner-qa/SKILL.md)
- **스킬 목적:**
  1. 부동소수점 오차 방지 및 소수점 셋째 자리 버림(Floor) 규칙 강제
  2. 동일 재료명-단위 완전 일치 항목만 합산하는 엄격한 그룹화 원칙 준수
  3. 로컬스토리지 고아(Orphan) 데이터 자동 정리 및 방어 절차 수립
- **작업 방식:** AI 에이전트가 각 단계 코드를 구현할 때 이 스킬의 지침을 읽고 준수하여, 매번 중복된 프롬프트 설명 없이도 엣지 케이스를 자가 점검하고 검증 보고서를 작성할 수 있었습니다.

## 5. 느낀점 및 결론

 Ai를 사용한 개발을 직접 경험해보니, 각종 오류에 대한 예외 처리에서의 도움, 디자인 적인 면에서 Ai가 기초를 잡아주는 것 등이 큰 도움이 되었습니다. 원하는 방향을 확실하게 말한 덕분인지 에이전트가 작성한 기능들은 제가 생각한대로 훌륭하게 작동했고, 피드백을 제시할 경우 즉각적으로 이를 처리해주는 등 피드백 루프가 반복되는 주기가 다인 개발에 비해 압도적으로 빨라져 개발에 있어 인력이 사용될 부분을 크게 대체할 수 있음을 실감했습니다. 한 번에 모든 작업물을 완성하는 대신 Todo 리스트를 차례대로 완성시키는 방식은 오류 지점을 발견하거나 피드백이 필요한 요소를 제시할 때 큰 도움이 되었으며, 뿐만 아니라 개발 중 다른 원하는 기능을 추가할 수 있다는 장점이 있었습니다. 애플리케이션 개발에 대해서는 경험이 많지 않았는데, Ai가 작성한 코드를 확인하며 학습할 경우 또한 유용할 것으로 보입니다.
